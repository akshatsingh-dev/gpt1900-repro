# PART 1: What you need to understand first

## The project in four sentences

Someone trained an AI only on writing from before 1900, then asked it 8 physics
questions whose answers were published after 1900, and had another AI grade the
answers out of 5. The published score is 0.93 out of 5.

Keating's view is that the idea is good but the numbers are not yet trustworthy.
My job is to check whether anyone could get those numbers again.

## Five words that will come up

**Checkpoint.** A saved copy of the model at one point in training, like a save
file in a game. There are 89 of them listed.

**Temperature.** A dial for how much the model gambles when picking each word.
At 0 it always takes its top choice, so the same question gives the same answer
every time. Above 0 it rolls a weighted dice. Theirs is set to 0.7.

**Seed.** The starting number for that dice. Write it down and anyone can replay
the exact same "random" answers forever. Lose it and nobody can, including the
people who ran it.

**Revision.** The version id of a model file on Hugging Face. Names can be
overwritten with new weights, so a name without a revision does not tell you
which model you actually got.

**The judge.** They did not grade by hand. Every answer went to the Claude API
and came back with a score from 0 to 5. So the grader is itself an AI.

## The two claims people confuse

**"I can do it again"** means you re-run it and get the same thing.

**"You can do it too"** means someone else, on their own machine, gets the same
thing.

Science needs the second one. A result that only works on the machine that made
it is not something anyone can build on. Almost everything below is about how
far GPT-1900 is from either.

# PART 2: The problems, explained

## Problem 1: There is no seed. Anywhere.

**Plain words.** I searched their entire evaluation script for the word "seed".
It appears zero times. The dice has no recorded starting number, so no answer
can ever be regenerated. Not by me, and not by them.

**The number.** 0 occurrences in `scripts/physics_eval.py`. [E016]

**Why it matters.** Their randomness is switched on by default at temperature
0.7. Randomness on, plus no seed, equals a fresh unrepeatable draw every run.

**Say this:** "Their eval script never sets a seed. I searched for it and it
does not appear once. With sampling on at 0.7, that means no generation in the
repository can be regenerated by anybody."

## Problem 2: The results do not repeat, and I measured it

**Plain words.** They have two pairs of runs where the same test was done twice.
I compared them answer by answer.

**The numbers.**

| Pair | Questions compared | Identical answers |
|---|---|---|
| `v8` vs `v8_det` | 96 | **0** |
| `v11` vs `v11_replication` | 24 | **2** |
| **Combined** | **120** | **2, which is 1.7%** |

I checked the prompts first: identical in all 120. So they were asked the same
things and gave different answers. [E014, E021]

**Say this:** "Across 120 paired answers where the prompts are byte-identical,
2 matched. 1.7 percent. Two separate pairs of runs, both behaving the same way."

## Problem 3: The settings were never saved

**Plain words.** For every answer they saved three things: the question, a word
called `mode`, and the answer. They never saved the settings used to produce it.

It is a recipe card that says "baked" with no oven temperature and no time. You
have the cake. You cannot make it again.

**The detail.** Line 609 of their script writes the results file. The settings,
`temperature`, `top_k`, `num_samples`, `max_tokens`, are sitting three lines
above it and are left out. So are the hardware details. [E017, E018]

**Why it matters.** It means I can prove the answers do not repeat but I cannot
prove why, and the reason I cannot is itself the problem.

**Say this:** "The fix is not a redesign. Line 609 writes the record, and the
settings are already in scope three lines up. It is roughly ten lines."

## Problem 4: They do not pin the model version either

**Plain words.** When their script downloads a model it asks by name and takes
whatever is there at that moment. If someone uploads new weights under the same
name tomorrow, the script quietly gets different weights and nothing says so.

**The number.** 0 occurrences of `revision` in the script. [E020]

**Why it matters.** This sits above the seed problem. The seed decides which
answer you draw. The revision decides which model draws it. Fixing the seed
without fixing this still leaves you unable to say what you ran.

**Say this:** "There is a second gap upstream of the seed. They download by name
with no revision pinned, so even a perfectly seeded run could silently use
different weights a month later."

## Problem 5: No repeat run was ever graded

**Plain words.** Their pipeline has two stages. Stage one makes the answers.
Stage two sends them to the Claude API for scoring. Both original runs did both
stages. Both repeat runs stopped after stage one.

**The detail.** There is a `--skip-judge` flag. So nothing crashed and nobody
forgot, it was chosen. My guess is cost, since grading is a paid API call and
skipping it on an exploratory run is ordinary practice. [E016]

**Why it matters.** No reproducibility figure for the score itself has ever been
computed. Not by them, not by anyone.

**Say this:** "Both repeat runs used `--skip-judge`, so neither was scored. I
assume that was to save API cost, which is reasonable, but it does mean nobody
has ever checked whether the 0.93 reproduces. I would rather ask than assume."

## Problem 6: The repeat runs were not configured like the originals

**Plain words.** Their script can ask each question several times. In both
pairs, the original and the repeat used a different number of tries.

**The numbers.** `v11` original: 1 answer per question. `v11_replication`: 3.
`v8`: 3 per question. `v8_det`: 1. [E022]

**Why it matters.** A replication should hold everything constant except what
you are testing. Here a setting changed and, because settings are not recorded,
you can only tell by counting the answers in the file.

I gave the repeat runs the benefit of the doubt and checked whether **any** of
the three tries matched the original, not just the first. It made no difference:
still 0 of 96, still 2 of 24.

**Say this:** "The two runs in each pair used different sample counts, so they
are not strictly like-for-like. I checked whether any of the three tries matched
rather than just the first, and the numbers do not move."

## Problem 7: 54 of 89 checkpoints were never released

**Plain words.** Their checkpoint list has 89 entries. 54 of them point at
"local", meaning weights that exist only on the author's own computer.

**Why it matters, and this one cuts against me.** My strongest number, 0 out of
96, comes from the v8 pair. Those weights are unreleased. So I can prove their
two saved runs disagree, but nobody can re-run either side to check. Including
me. It is evidence about their files, not a reproduction anyone could repeat.

**And the good news in the same fact.** Of the 35 that are downloadable, 24
belong to the v11 family. 24 checkpoints times 8 questions is 192, which is
exactly the number of graded scores in the published run. **So the published
result rests on weights anyone can get.** That is where my own run should go,
and I am switching to it. [E020]

**Say this:** "I want to flag a limit on my own headline number before someone
else does. The v8 weights were never published, so that comparison is about
their saved files rather than something an outsider could repeat. The v11 family
is public, it is what the published 192 scores come from, and that is where I am
pointing my own run."

## Problem 8: The model has a stereotyped opening

**Plain words.** I read the actual answers. Most of them start with the exact
same phrase.

**The numbers.** Of 192 answers in the published v11 run, **150, or 78%, begin
with "You have touched..."**. In the three checkpoints that were replicated it
is 95 of 96, 98%. In the older v8 run, which was prompted differently, it is 0
of 288. [E023]

**Why it matters.** Two reasons, and both are worth a physicist's attention.

First, it makes any similarity measure look better than reality. When I measured
how far two answers agree before diverging, the v11 pairs agreed for about 900
characters. That looks like near-determinism until you notice they were agreeing
on boilerplate, not on physics.

Second, and more importantly, the grader is an AI scoring free text. If most
answers open in the same confident period voice, it is fair to ask whether the
score partly reflects style rather than reasoning. I am not claiming it does. I
am saying nobody has checked, and it is checkable.

**Say this:** "78 percent of the published answers start with the same phrase.
That inflates any text-similarity measure, and it raises a question I cannot
answer yet: is the judge rewarding a convincing period voice, or actual physics?
That is one of the things a blind physicist review would settle."

## Problem 9: Two of the eight questions sit on the training boundary

**Plain words.** The model was supposedly trained only on pre-1900 writing.

`uv_catastrophe` asks for Planck's law, published October and December **1900**.
That is on the line, not past it.

`sr_michelson_morley` refers to an experiment from **1887**, which is inside the
training data. Only the 1905 explanation is outside.

**Why it matters.** Six of the eight questions are clean. Those two are testing
something different and probably should not be averaged in with the rest without
saying so. It also turns a vague worry about contamination into one specific
query: does the corpus contain anything dated 1900, and does any of it mention
Planck. [E011]

## Problem 10: The grader is not pinned either

**Plain words.** Scores come from the Claude API, which is a hosted service that
gets updated. No grader version is recorded anywhere. So you could freeze the
answers perfectly and the scores would still move, because the grader changed
underneath you. There is also only one grader and no human check, so there is no
way to tell a real change from grader drift.

**Say this, as a question not a conclusion:** "My instinct is that the grader
should be pinned like any other instrument, and that we need at least two raters
to get an agreement number. But you all know measurement better than I do. Is
that the right call?"

## Problem 11: Looked at properly, the scores barely move

**Simple version.** I had only ever seen the average, 0.93. I opened the actual
score table. **86 percent of all 192 scores are either 0 or 1.** A 5 never
happened once. Four of the eight questions only ever scored 0 or 1, so on those
the 0-to-5 rubric is really a yes/no.

**The numbers.** Recomputed mean 0.932, matching the published figure. 0 appears
44 times, 1 appears 122 times, 2 appears 22 times, 3 three times, 4 once, 5
never. [E024]

**What I am not saying.** Not that the scoring is wrong. If the answers are
uniformly poor then uniformly low scores are the right measurement. What it does
mean is that any comparison between checkpoints rests on the few cells that
actually move, and a tenth of a point in an aggregate is hard to read with no
uncertainty attached to it.

**The half that favours the work, and say this too.** The mean rises from 0.62
across the first eight checkpoints to 1.11 across the last eight. Close to a
doubling over RL training. The measurement is detecting real improvement.

**Say this:** "86 percent of the scores are 0 or 1 and the top of the scale is
never used, so the rubric has very little resolution over this model. But it does
detect real improvement across training, 0.62 to 1.11, and that deserves saying."

## Problem 12: Changing the wording moves scores as much as the whole signal

**Simple version.** Two different phrasings of the questions were both graded, so
I could compare them with no download. Changing only the wording moves a
question's score by up to 1.3 points, on a benchmark whose overall average is
about 1.3.

**The numbers.** Scaffolded prompts against minimal ones, 3 shared checkpoints,
24 scores each. The overall difference is small, +0.12, but it hides large swings
in both directions: Michelson-Morley +1.10, free fall +0.67, photoelectric -1.33,
elevator -0.90. [E025]

**The confound, and I want to state it myself.** The minimal condition averaged
three samples per cell and the scaffolded one used a single sample, so the two
differ in more than the prompt. Coverage is also 3 of 24 checkpoints. I would
want to run this properly before standing behind a number.

**Why it is interesting anyway.** The movement goes both ways. A prompt leaking
part of the answer would raise scores uniformly. Some tasks score *better* with
less scaffolding, which is more interesting than plain leakage and is worth a
real experiment.

**Say this:** "Prompt wording appears to move individual task scores by up to
1.3 points on a benchmark that averages 1.3 overall. But the two conditions also
used different sample counts and only 3 of 24 checkpoints, so I would want to run
it properly before standing behind that. It is the prompt-leakage threat in 13.2
and it is the only quantitative handle on it so far."

## One thing I think is missing from Section 13

Offered as a suggestion, not a correction.

13.3 covers variance and cherry-picking, and both assume the run could in
principle be repeated. The stronger failure here is that **no run in the
repository can be regenerated at all**, because no seed was ever set. That is not
sampling bias, it is a record-keeping failure, and it sits upstream of every
control in Section 11. The withheld-prediction and preregistration machinery all
assume you can freeze a candidate and re-derive it. You cannot freeze what you
cannot reproduce.

Two smaller ones alongside it: the download resolves a mutable model name with no
revision pinned, so weights can change silently between runs; and the judge model
version is not recorded, so scores can move with the generations held fixed.

# PART 8: If they ask

**"Are you saying their result is wrong?"**
No. I am saying nobody can check it, including them. The score might be exactly
right. There is currently no way to find out, and that is a fixable problem
rather than a fatal one.

**"Isn't randomness normal in language models?"**
Yes, and it is fine. What is not fine is randomness with no recorded seed. With
a seed you get variety and repeatability at the same time. That is the whole
fix for this part.

**"Why does it matter if answers differ but scores are similar?"**
Good question and I cannot answer it yet, because no repeat run was ever scored.
That is exactly the gap. Getting a scored repeat run is one of my next steps.

**"How much of this is a real problem versus normal research code?"**
Most of it is normal research code, honestly. It becomes a real problem the
moment a number from it goes into a paper. My read is that the pipeline was
built to explore and is now being asked to measure, and those need different
standards.

**"What is the single most important thing to fix?"**
The seed, because it is small and it unlocks everything else. Right behind it,
pinning the model revision and the judge version. Together those are maybe a day
of work and they turn every future run into evidence.
