## The script that matters

`scripts/physics_eval.py`, 653 lines. This is the pipeline that produced the
published result.

| Column | Verdict |
|---|---|
| **Exists** | Yes |
| **Runs** | **Not tested.** No install attempted |
| **Reproduces** | **No.** 2 of 120 paired generations identical, 1.7% [E014, E021, E022] |
| **What it logs** | 3 fields per generation: `prompt`, `mode`, `completions` [E010] |
| **Gaps** | No seed, no model revision, sampling parameters discarded at the write [E016, E017, E020] |

### What it does

Two stages. Stage one downloads a checkpoint, generates answers to 8 physics
tasks, writes `generations.json`. Stage two sends those answers to the Claude API
for scoring, writes `results_judged.json` and `summary.txt`. Stage two is
skippable with `--skip-judge`.

### Gaps, each traced to a line

| Gap | Evidence | Consequence |
|---|---|---|
| No seed anywhere | 0 occurrences of `seed` in the file [E016] | No generation can be regenerated by anyone, including the authors |
| Sampling on by default | `--temperature` 0.7, `--top-k` 50, lines 532 to 533 [E016] | Every run is a fresh draw |
| Settings discarded at the write | Written at line 609; `temperature`, `top_k`, `num_samples`, `max_tokens` in scope at lines 595 to 604 [E017, E018] | Cannot determine what produced any archived answer |
| Hardware discarded | `device`, `num_gpus` in scope, not written [E018] | Cannot assess whether results transfer between machines |
| No model revision | 0 occurrences of `revision`; `snapshot_download` resolves a mutable name [E020] | Weights behind a name can change silently between runs |
| Record keyed on name alone | `all_generations[ckpt.name]` at line 606 [E018] | Same key can refer to different weights |
| Judge version not recorded | No judge model or version in any output file | Scores can move with generations held fixed |
| No test coverage | `tests/` holds 3 files, none touching `physics_eval.py` | The script producing the paper's number is untested |

### What it does well

- Writes results after every checkpoint, commented for crash resilience, so a
  failure late in a sweep does not lose the earlier work [E018].
- Deletes each downloaded checkpoint after evaluating it, and filters the
  download with `allow_patterns` to one step's weights plus tokenizer, so peak
  disk is one checkpoint rather than the whole collection [E018, E020].

That second point resolved the disk constraint flagged at the start of the week.
31GB is sufficient for a sequential sweep.

**Reproducibility measured across the two available pairs** [E014, E021, E022]:

| Pair | Prompts identical | Answers identical | Total |
|---|---|---|---|
| `v8` vs `v8_det` | 96 of 96 | **0** | 96 |

| **Combined** | **120 of 120** | **2, 1.7%** | **120** |

Both figures were re-tested allowing a match against any stored sample rather
than only the first. Neither moved.

Neither pair is strictly like-for-like: in both cases the run and its repeat used
different `--num-samples` values, detectable only by counting entries in the
output files because no invocation parameters are archived [E022].

**Output characterisation** [E023]. 150 of 192 generations in the published run,
78%, open with the identical phrase "You have touched". Restricted to the three
replicated checkpoints it is 95 of 96. In `physics_eval_v8`, run in completion
mode, the phrase occurs in 0 of 288 outputs. This inflates any prefix-similarity
measure and raises an open, checkable question about whether an LLM judge scoring
free text partly tracks stylistic register.
